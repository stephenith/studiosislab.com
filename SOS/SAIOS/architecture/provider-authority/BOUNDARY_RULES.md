# Provider Boundary Rules

**Agent #192 · Architectural boundary enforcement**  
**Mechanism:** static import scan in `provider-authority:verify`  
**Not** Runtime Guard · **Not** a framework · **No** runtime overhead

---

## Invariant

```
Worker Runtime · Department SDK · Company Brain · Scheduler · Queue · Execution Controller
        ✕ must not import ✕
core/providers/** · vendor SDKs · BrainRouter / MockProvider / executeViaMockProvider
```

**BrainRouter** (via Skills / ResumeBrainGateway and related core gateways) remains the **only** provider reasoning entrypoint.

Runtime Guard (`architecture/runtime-guard.ts`) continues to own **execution engines only**. Provider import boundaries are enforced here, at verify time.

## Forbidden import patterns

A `.ts` / `.tsx` / `.js` / `.mjs` / `.cjs` file under a forbidden root fails verify if any import / require string matches:

1. `core/providers` or `/providers/mock` (provider adapters)  
2. Vendor SDKs: `openai`, `@anthropic`, `@google/generative-ai`, `@google/genai`  
3. Provider entrypoints: `BrainRouter`, `executeViaMockProvider`, `MockProvider`, `createMockProvider`  
4. Path `ai-brain/providers` (reserved; must not appear)

Allowed elsewhere (not under forbidden roots): `core/skills`, `core/resume-integration`, `core/providers/mock`, `core/ai-brain`, `core/provider-validation`, verifies.

Skills / ResumeBrainGateway

Forbidden consumers request work through Company Brain / queue / execution contracts — **never** by importing providers.
